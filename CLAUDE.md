## Product summary

Nouttbuk is a note-taking app for university students that combines a private, per-subject note library with an academic community feed. The single core mechanic is that every note (`apunte`) has a visibility level set individually: `private` (owner only), `group` (owner + invited collaborators with `read`/`edit` permission), or `community` (publishes to a public feed, readable without login; this is the growth/SEO hook and must never be regressed). Reactions and saves on community posts are per-user rows, not global counters.

MVP is scoped to a single university (Pontificia Universidad Católica del Perú): signup is rejected unless the email ends in `@pucp.edu.pe`, enforced both client-side (`src/lib/auth/dominio-institucional.ts`) and at the database level (trigger in `supabase/migrations/20260817204401_auth_domain_restriction.sql`). Multi-university support is explicit v2.0 scope (see `STACK.md`).

## Stack

Next.js 16 (App Router, TypeScript) + Supabase (Postgres/Auth/Storage/Realtime) + Tailwind CSS v4 + shadcn/ui (`base-nova` style, over `@base-ui/react`, **not** Radix) + Tiptap (editor, not yet integrated) + Liveblocks (real-time co-editing, `group`-visibility notes only, not yet integrated) + Motion (motion.dev, everyday micro-interactions, not yet integrated) + anime.js v4 (2-3 signature moments only, not yet integrated) + Phosphor icons (`@phosphor-icons/react`) + Vercel.

The visibility model (`private`/`group`/`community`) is enforced via Postgres **Row Level Security**, not hand-rolled authorization checks in application code. Public feed reads and authenticated writes (react/save/comment/create) are designed as separate query/mutation paths.

## Architecture

**Supabase client pattern** (`src/lib/supabase/`): three separate client factories, standard `@supabase/ssr` split — `client.ts` (browser, used from Client Components and the auth forms), `server.ts` (reads/writes cookies via `next/headers`, used from Server Components/route handlers), `middleware.ts` (`updateSession`, refreshes the session cookie on every request). `middleware.ts` is wired in via `src/proxy.ts` (Next.js 16's replacement for the old `middleware.ts` convention at the project root) — it only refreshes cookies, it does not redirect; route protection happens in each gated page, not centrally.

**Route structure** (`src/app/`): a `(shell)` route group holds the four nav destinations behind one shared layout. `(shell)/layout.tsx` is a Server Component that reads the session once (`auth.getUser()` + a `profiles` lookup) and passes it as a plain prop to `AppShell` (`src/components/nav/app-shell.tsx`, a Client Component that owns nav state and the auth modal). Deliberate decision: `(shell)/page.tsx` (`/`) is the public Comunidad feed with **no auth check**, so it can never accidentally end up gated behind a login wall — this is the SEO/growth-hook route from the product rules above. `/inicio`, `/apuntes`, `/perfil` are Server Components that call `redirect("/?login=1")` when there's no session; `AppShell` reads that query param in an effect (keyed on `pathname`, not mount, since a server-side redirect during a client navigation reuses the existing shell instance instead of remounting it) and auto-opens the login modal.

**Design tokens** (`src/app/globals.css`): the Tailwind v4 `--radius-*` scale is *not* derived from a single multiplier — cards/dialogs/sheets need 26px (`--radius-xl`) and buttons/inputs/selects need 14px (`--radius-lg`) simultaneously, which a single-base chain can't produce, so each step of the scale is set to an explicit value. Colors follow DESIGN-SYSTEM.md's Indigo/Teal/Slate tokens with distinct light/dark values (not auto-inverted).

**Icons**: `@phosphor-icons/react`'s default export needs a client boundary (it isn't RSC-safe); the package ships a separate `@phosphor-icons/react/dist/ssr` entry that is. Use the plain import inside Client Components (shadcn-generated `src/components/ui/*` and anything under `src/components/nav/`, `src/components/auth/`), and the `/dist/ssr` import inside Server Components (the gated route pages in `src/app/(shell)/*/page.tsx`).

**shadcn/ui components** (`src/components/ui/`): generated via `npx shadcn add <name>` using this project's `base-nova` style (`components.json`, `iconLibrary: "phosphor"`) over `@base-ui/react` primitives — the generated API shape (prop names, `render` prop patterns, `data-slot` attributes) follows Base UI conventions, not Radix's, even though it looks similar. Check a freshly-generated file's actual output before assuming an API from Radix-based shadcn docs.

**Auth forms** (`src/components/auth/`): `login-form.tsx`, `signup-form.tsx`, `recuperar-form.tsx` are composed inside `auth-modal.tsx` (a fully controlled `mode`/`open` component, no internal state), all reachable from `AppShell`. Supabase Auth error messages are normalized to Spanish copy in one place, `src/lib/auth/mapear-error-auth.ts` (tested in `tests/mapear-error-auth.spec.ts`), rather than string-matched inline in each form. Signup passes `nombre`/`usuario`/`carrera` via `signUp({ options: { data: {...} } })`; it never inserts into `profiles` directly, that row is created by the `handle_new_user` DB trigger.

## Language rule for all user-facing text

All copy (UI strings, error messages, docs, comments, and any reply written in this project) must be in **neutral/standard Spanish** ("tú" forms). Never Rioplatense/Argentine Spanish (no "vos", no voseo conjugations like "tenés"/"podés"/"hacé"). This has been corrected multiple times in this project; treat it as a hard constraint, not a style preference, and re-check any generated string against it before finalizing. Also avoid em dashes as a sentence/clause separator, use commas or split sentences instead; this is a separate, equally strong standing preference in this project.

Several things worth knowing if you touch this area again:

- **The editor is a `position: fixed` full-screen overlay, not a separate route layout.** `src/app/(shell)/apuntes/nuevo/page.tsx` and `.../[id]/editar/page.tsx` are plain routes inside the `(shell)` group (so the auth-gate pattern stays consistent), but `ApunteEditor` renders `fixed inset-0 z-50 bg-background`, which visually covers the sidebar nav without needing a second route tree outside `(shell)`. This satisfies design.md's "overlay de pantalla completa con salida explícita" for Editor without the complexity of a parallel layout.
- **Tiptap needs `immediatelyRender: false` in `useEditor()`** to avoid an SSR hydration mismatch (ProseMirror needs the real browser DOM, so the first render can't try to match server output) — this is a known Tiptap + Next.js App Router gotcha, not optional.
- **Base UI's `Select` needs an `items` prop, not just `SelectItem` children, to show a friendly label in the closed trigger.** Without `items={{value: "Label", ...}}` on `Select` (the `Root`), `SelectValue` displays the raw `value` string (e.g. `__ninguna__`, `private`) instead of the item's rendered label — this bit both the carpeta selector and the visibilidad selector in the editor until fixed. Reuse the `items` pattern (see `apunte-editor.tsx`) anywhere else `Select` is used with non-self-explanatory values.
- **`Badge` and `Tabs` (base-nova/Base UI) are now in `src/components/ui/`**, added for etiqueta chips and the Todos/Favoritos/Compartidos tabs respectively.
- **"Grupo" visibility shows a visible-but-disabled collaboration stub** (coedición en vivo + "Invitar colaborador") in the editor — real behavior is `todo.md` items 7 (compartir/colaboración) and 8 (Liveblocks coedición), both later. Same "build the honest UI now, wire it up when the dependency ships" discipline as `NuevoApunteButton` used to follow.
- **The `sync_publicacion` trigger and RLS visibility pipeline (already built and pgTAP-tested in an earlier phase) were verified end-to-end through the new editor for the first time**: setting visibilidad to `community` from the UI does create a `publicaciones` row automatically, confirmed via direct DB check during this session's manual testing.

- **`Button` cannot be imported directly into a Server Component page** unless the file itself (or one of its own imports) declares `"use client"`. `src/components/ui/button.tsx` has no directive of its own — it only becomes a client boundary transitively, via `@base-ui/react/button`'s internal directive — and it imports `CircleNotchIcon` from the plain, non-SSR `@phosphor-icons/react` entry point, which creates React context at module scope. Fixed at the root this time: `src/components/nav/fab-nuevo-apunte.tsx` (`NuevoApunteButton`) now has `"use client"` directly, so it's safe to import from any Server Component page without a wrapper. `src/components/inicio/inicio-acciones.tsx` remains as the pattern to copy for any *other* raw `Button` usage that needs to live directly in a Server Component (e.g. `src/components/apuntes/carpeta-sheet.tsx` and `apuntes-explorer.tsx` already do this correctly, both are `"use client"` themselves). Also: `Button` rendered as a `<Link>` via the `render` prop needs `nativeButton={false}`, or Base UI logs a console warning about native button semantics (see `carpeta-sheet.tsx`).
- **A component with `useState(prop ?? default)` needs a `key` tied to that prop's identity, or it goes stale across a client-side route/prop change.** `CarpetaSheet` seeds its `nombre`/`color` state from an optional `carpeta` prop; when the header's "Nueva carpeta" button became "Editar carpeta" after a client-side navigation to `?carpeta=X` (Sprint 3), React reused the same mounted instance and kept the old (empty/default) state instead of picking up the new prop. Fixed with `key={carpetaActiva?.id ?? "nueva"}` at the call site in `apuntes/page.tsx`. Watch for this pattern anywhere else a sheet/dialog/form seeds its initial state from a prop that can change identity without the component unmounting.
- **Table-level `GRANT`s were missing for every RLS-protected table.** Discovered because `/inicio`'s `profiles` query returned `permission denied for table profiles` (Postgres 42501) even though the RLS policy allowed it — Postgres checks base table privileges before RLS, and this project's `postgres` role (the one migrations run as) has a local default privilege that withholds select/insert/update from `anon`/`authenticated` on new tables, unlike `supabase_admin`. This had never been caught because `supabase/tests/database/` (pgTAP) had never actually been run against a real Postgres instance before (Docker wasn't available in the session that wrote them). Fixed in `supabase/migrations/20260818053857_table_grants.sql`, one `grant` per table matching each RLS policy's role/action scope. `npm run db:test` now fully passes `20_apuntes_visibilidad.test.sql` and `30_social_reacciones_comentarios.test.sql` (previously failing/erroring). Two unrelated, pre-existing pgTAP issues remain and are NOT fixed: `00_setup.test.sql`'s `has_table()`/`has_schema()` calls fail (function signature mismatch with the pgtap version this local stack installs, needs investigation), and `10_profiles_domain.test.sql` test 1 expects SQLSTATE `P0001` but the domain-restriction trigger actually raises `23514` (a `CHECK` constraint violation code, not a custom-raised exception) — the trigger itself works correctly, only the test's expected error code is wrong.
- **Shared, cross-feature UI now lives outside `components/inicio/`.** `SeccionVacia` moved to `src/components/shared/seccion-vacia.tsx` (used by both Inicio and Mis apuntes). `MateriaRecienteCard` and `ApunteRecienteCard` stayed under `src/components/inicio/` but are also imported from `apuntes/page.tsx` and `apuntes-explorer.tsx` — pragmatic reuse rather than a rename, since renaming would touch working, tested call sites for no functional gain. `src/lib/carpetas/colores.ts` is the single source of truth for the coral/amber/violet/blue folder-color token mapping, shared by the materia card and `CarpetaSheet`'s color picker.
