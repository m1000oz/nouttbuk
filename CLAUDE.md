## Product summary

Nouttbuk is a note-taking app for university students that combines a private, per-subject note library with an academic community feed. The single core mechanic is that every note (`apunte`) has a visibility level set individually: `private` (owner only), `group` (owner + invited collaborators with `read`/`edit` permission), or `community` (publishes to a public feed, readable without login; this is the growth/SEO hook and must never be regressed). Reactions and saves on community posts are per-user rows, not global counters.

MVP is scoped to a single university (Pontificia Universidad Católica del Perú): signup is rejected unless the email ends in `@pucp.edu.pe`, enforced both client-side (`src/lib/auth/dominio-institucional.ts`) and at the database level (trigger in `supabase/migrations/20260817204401_auth_domain_restriction.sql`). Multi-university support is explicit v2.0 scope (see `STACK.md`).

## Stack

Next.js 16 (App Router, TypeScript) + Supabase (Postgres/Auth/Storage/Realtime) + Tailwind CSS v4 + shadcn/ui (`base-nova` style, over `@base-ui/react`, **not** Radix) + Tiptap v2 (editor; pinned below v3 because `@liveblocks/react-tiptap` requires Tiptap v3 and this project uses a manual Yjs integration instead, see the Liveblocks note below) + Liveblocks (`@liveblocks/client`/`react`/`yjs`/`node`, real-time co-editing for `group`-visibility notes with `edit` permission) + Motion (motion.dev, everyday micro-interactions) + anime.js v4 (a few signature moments, e.g. the Comunidad hero) + jsPDF (client-side CV PDF generation, dynamically imported) + Cloudflare Turnstile (CAPTCHA on signup/login/recover, code-complete but shipped disabled pending real credentials) + Phosphor icons (`@phosphor-icons/react`) + Vercel (not yet deployed).

All four `@liveblocks/*` packages must be pinned to the exact same minor version; mixing majors (e.g. `@liveblocks/node@^3` against `@liveblocks/client@2.24.4`) loads two incompatible copies of `@liveblocks/core` and Liveblocks throws a runtime "dupes" error.

The visibility model (`private`/`group`/`community`) is enforced via Postgres **Row Level Security**, not hand-rolled authorization checks in application code. Public feed reads and authenticated writes (react/save/comment/create) are designed as separate query/mutation paths.

## Architecture

**Supabase client pattern** (`src/lib/supabase/`): three separate client factories, standard `@supabase/ssr` split — `client.ts` (browser, used from Client Components and the auth forms), `server.ts` (reads/writes cookies via `next/headers`, used from Server Components/route handlers), `middleware.ts` (`updateSession`, refreshes the session cookie on every request). `middleware.ts` is wired in via `src/proxy.ts` (Next.js 16's replacement for the old `middleware.ts` convention at the project root) — it only refreshes cookies, it does not redirect; route protection happens in each gated page, not centrally.

**Route structure** (`src/app/`): a `(shell)` route group holds the four nav destinations behind one shared layout. `(shell)/layout.tsx` is a Server Component that reads the session once (`auth.getUser()` + a `profiles` lookup) and passes it as a plain prop to `AppShell` (`src/components/nav/app-shell.tsx`, a Client Component that owns nav state and the auth modal). Deliberate decision: `(shell)/page.tsx` (`/`) is the public Comunidad feed with **no auth check**, so it can never accidentally end up gated behind a login wall — this is the SEO/growth-hook route from the product rules above. `/inicio`, `/apuntes`, `/perfil` are Server Components that call `redirect("/?login=1")` when there's no session; `AppShell` reads that query param in an effect (keyed on `pathname`, not mount, since a server-side redirect during a client navigation reuses the existing shell instance instead of remounting it) and auto-opens the login modal.

**Design tokens** (`src/app/globals.css`): the Tailwind v4 `--radius-*` scale is *not* derived from a single multiplier — cards/dialogs/sheets need 26px (`--radius-xl`) and buttons/inputs/selects need 14px (`--radius-lg`) simultaneously, which a single-base chain can't produce, so each step of the scale is set to an explicit value. Colors follow DESIGN-SYSTEM.md's Indigo/Teal/Slate tokens with distinct light/dark values (not auto-inverted).

**Icons**: `@phosphor-icons/react`'s default export needs a client boundary (it isn't RSC-safe); the package ships a separate `@phosphor-icons/react/dist/ssr` entry that is. Use the plain import inside Client Components (shadcn-generated `src/components/ui/*` and anything under `src/components/nav/`, `src/components/auth/`), and the `/dist/ssr` import inside Server Components (the gated route pages in `src/app/(shell)/*/page.tsx`).

**shadcn/ui components** (`src/components/ui/`): generated via `npx shadcn add <name>` using this project's `base-nova` style (`components.json`, `iconLibrary: "phosphor"`) over `@base-ui/react` primitives — the generated API shape (prop names, `render` prop patterns, `data-slot` attributes) follows Base UI conventions, not Radix's, even though it looks similar. Check a freshly-generated file's actual output before assuming an API from Radix-based shadcn docs.

**Auth forms** (`src/components/auth/`): `login-form.tsx`, `signup-form.tsx`, `recuperar-form.tsx` are composed inside `auth-modal.tsx` (a fully controlled `mode`/`open` component, no internal state), all reachable from `AppShell`. Supabase Auth error messages are normalized to Spanish copy in one place, `src/lib/auth/mapear-error-auth.ts` (tested in `tests/mapear-error-auth.spec.ts`), rather than string-matched inline in each form. Signup passes `nombre`/`usuario`/`carrera` via `signUp({ options: { data: {...} } })`; it never inserts into `profiles` directly, that row is created by the `handle_new_user` DB trigger.

**Auth gate outside the shell's redirect-based flow** (`src/components/nav/auth-gate.tsx`): `AuthGateProvider`/`useAuthGate()` wraps the shell's `<main>`, reusing `AppShell`'s existing `abrirAuth("login")` closure. Gated *pages* (`/inicio`, `/apuntes`, `/perfil`) use the `redirect("/?login=1")` + query-param mechanism described above, but content that's optionally-authenticated on an otherwise-public page (Comunidad's reaccionar/guardar/comentar) can't rely on that, since the page itself never redirects. Any component under the shell can call `useAuthGate().abrirLogin()` to open the login modal from wherever it's rendered.

**Aggregate counts blocked by RLS** (`get_publicacion_counts`, `get_perfil_stats`, migrations in `supabase/migrations/`): when a screen needs a count across *other* users' rows that RLS won't let the caller read directly (e.g. reactions received on your own publications, or public reaction counts for `anon`), the pattern is a narrow `security definer set search_path = '' stable` SQL function living in `public` (not `private`, which is reserved for internal RLS-policy helpers), granted only to the roles that actually need it (`anon, authenticated` for feed-facing counts, `authenticated` only for own-profile stats — never bare `grant ... to public`). Don't reach for client-side joins or loosen RLS instead.

**Sheet vs. full-screen overlay**: two distinct overlay patterns, chosen by how much the screen holds, not by how it's reached. Small single-entity edits (`carpeta-sheet.tsx`, `editar-perfil-sheet.tsx`) use `Sheet`/`SheetContent(side="bottom")` from `src/components/ui/sheet.tsx`, with local `open`/`cargando`/`error` state and `router.refresh()` on success. Full destinations (`apunte-editor.tsx`, `detalle-publicacion.tsx`) render a plain `fixed inset-0 z-50` div from a normal route inside `(shell)`, instead of a nested layout, so they cover the sidebar nav without a second route tree.

**Recurring gotchas**: Tiptap's `useEditor()` needs `immediatelyRender: false` (otherwise an SSR hydration mismatch, since ProseMirror needs the real browser DOM). Base UI's `Select` needs an `items` prop (not just `SelectItem` children) or the closed trigger shows the raw value instead of the item's label; its popup width is `w-max min-w-(--anchor-width) max-w-[min(90vw,28rem)]` in `src/components/ui/select.tsx` specifically so a long, not-yet-selected option can't get clipped, don't reintroduce a hard `w-(--anchor-width)` lock there. A component that seeds `useState` from an optional prop needs a `key` tied to that prop's identity, or it goes stale when the prop changes without the component unmounting. A PostgREST embed between two tables with more than one relationship path (e.g. `apuntes`↔`profiles` via both `autor_id` and `colaboradores`) needs the explicit FK name (`profiles!apuntes_autor_id_fkey`), or the query silently returns `PGRST201`. RLS policies alone aren't enough for a new table: Postgres checks table-level `GRANT`s first, so every RLS-protected table also needs a matching grant (see `supabase/migrations/20260818053857_table_grants.sql`), and this must be considered explicitly even for the `anon` role on a table `anon` has no RLS policy on at all, otherwise a missing grant surfaces as a hard permission-denied error instead of the intended RLS-driven empty result (hit twice in this project's history, on `feedback` and once earlier, get it right on the first migration draft for any new table). A flex container with no explicit `align-items` defaults to `stretch`, which silently caps a `min-h-[...]`-only child's height at the container's own computed height instead of letting it grow with content (bit the editor's A4 "hoja" once); add `items-start` when a child should size to its content. pgTAP's `throws_ok(sql, errcode, description)` matches its third argument against the actual Postgres exception message, not a free-text description, unless a 4th argument is passed. There is no admin role anywhere in this app: status/moderation changes (`feedback.estado`, reviewing rows in `reportes_publicacion`/`reportes_comentario`) are done by hand via SQL or Supabase Studio, not a built UI, by design. Never combine two related pieces of text with a "·" middle dot or an em dash, both were removed everywhere on purpose (see the Language rule below), prefer a stacked two-line layout, a thin `bg-border` vertical rule, or a `Badge` instead. Any future `@liveblocks/*` package addition must be pinned to match the other four (`client`/`react`/`yjs`/`node`, currently all `2.24.4`) or Liveblocks throws a runtime "dupes" error. Any clickable control inside the note editor (toolbar button, menu trigger) that runs a Tiptap command needs `onMouseDown={(e) => e.preventDefault()}` in addition to its `onClick`: a plain `<button>`'s native `mousedown` behavior moves DOM focus to the button before `click` fires, which blurs the ProseMirror `contenteditable` for one tick, which can hide/reposition anything whose visibility or placement depends on `view.hasFocus()` or on measuring the document's current layout (hit repeatedly across editor sessions: the old BubbleMenu, and separately any control that changes something reflow-affecting like alignment or block style) — preventing the mousedown default keeps focus on the editor the whole time, so this class of bug can't happen at all, not just less often. Base UI's `Menu`/`Dialog` (and anything built on them, like `DropdownMenuContent`/`DialogContent`) portal to `document.body` by default, escaping any scoped CSS-variable override like `.apunte-editor-overlay`'s atelier tokens; both components now accept an optional `container` prop (a `RefObject<HTMLElement | null>`) threaded straight to the underlying Base UI `Portal`, so a component rendered inside a themed subtree can keep its popovers themed too instead of needing a hand-copied `!important` override class (see `editor-menu-bar.tsx`'s `overlayRef` for the pattern) — the older Select/Sheet-based popovers elsewhere in the editor header still don't pass this prop and still escape to the app's ambient theme, a known, accepted gap, not something this pattern retroactively fixed. A CSS rule that only redefines custom properties (`--foreground`, etc.) on a scoped class does **not** by itself recolor descendant text that relies on plain inheritance: a property inherits its *already-computed* value, not the `var()` expression, so an ancestor further up the tree (like `<body>`'s own `text-foreground`) can "win" for any descendant that never declares its own `color` — the fix is a `color: var(--foreground)` (or equivalent) declaration on the scoping class itself, not just the custom-property redefinitions (bit `.apunte-editor-overlay` itself, several header icons were invisible for two iterations before this was caught). `requestAnimationFrame` is not a safe way to schedule a non-animation layout recalculation triggered by content changes: rAF only runs when the browser is about to paint a new frame, which some rendering contexts (a backgrounded tab, an automation-controlled browser) can delay indefinitely or never do at all, silently freezing whatever depended on it (bit `pagination-extension.ts`'s `medirYDecorar`, confirmed via a bare rAF call that never fired for several seconds in a browser-automation session); `setTimeout(fn, 0)` runs unconditionally instead and is the correct tool for this class of work regardless of the testing-environment quirk that surfaced it. ProseMirror's `view.posAtDOM(node, 0)`, where `node` is a top-level block's own DOM element, returns the position just *inside* that node (before its first character), not the position before the node as a sibling — a `Decoration.widget` placed there renders as that node's own first child instead of a preceding sibling div; the fix is `posAtDOM(parentDom, childIndex)` (the position at that child-offset of the parent), which lands genuinely between siblings (see `pagination-extension.ts`'s page-break spacer). A `Decoration.widget` from a previous render pass is still a real DOM element until the next `dispatch` replaces it: any measurement loop over `dom.children` that doesn't explicitly skip old widgets will re-count their height as if they were content on every later recalculation, corrupting any threshold-based logic (page/chunk boundaries, etc.) for the second and later thresholds even after the first one works correctly; separately, an accumulator being compared against a "pure capacity" threshold must never have the computed gap/overflow amount folded back into itself, or every threshold after the first is reached too early. A percentage width (`w-full`) on an element whose parent has no definite width of its own (sized via CSS shrink-to-fit) contributes nothing to that parent's intrinsic-size calculation per spec; with too little other content to establish a natural width, the whole chain can collapse to just the innermost padding — give the child a definite pixel width instead (with `maxWidth: "100%"` for responsive shrink) when this pattern is unavoidable (bit `hojas-editor.tsx`'s page container on a brand-new, still-empty note). When a screenshot contradicts a direct `getComputedStyle`/DOM check in this environment, trust the computed check (or re-capture via `zoom`) before concluding something is visually broken — the plain screenshot action has been observed serving a stale cached frame for a region across several consecutive calls. Pasting plain text with single line breaks (no blank line between them) produces one paragraph with internal `hardBreak` nodes, not separate paragraphs, in both of ProseMirror's clipboard paths (plain-text fallback and HTML, since many real sources represent their own line breaks as `<br>`) — a block-level pagination scheme that can only break between whole top-level nodes then has to push that entire multi-line paragraph whole when it doesn't fit, wasting up to its full height; `clipboardTextParser` only fires when the clipboard has no HTML at all, so it's the wrong hook to normalize this — `editorProps.transformPasted` (see `src/lib/tiptap/pegar-lineas-como-parrafos.ts`) is the one hook ProseMirror always calls regardless of which path produced the slice, and both `editor-estatico.tsx` and `editor-colaborativo.tsx` configure `editorProps` separately, so a paste-behavior fix needs to be wired into both, not just one. A ProseMirror plugin's `update()` view hook fires synchronously inside `editorView.dispatch()`; if a "recalculation scheduled" flag is reset to `false` before that `dispatch` call (instead of after), the hook's own re-entrant call sees the flag already clear and reschedules an extra, usually-redundant pass on every single content change — reset debounce flags like this only once the dispatch that they guarded against has actually completed.

**The toast system** (`src/components/ui/toast.tsx`) is a hand-written adaptation of the shadcn `base-nova` registry's `toast` component (the CLI's `npx shadcn add toast` hung indefinitely once and was worked around by hand-copying the registry output), it exports a singleton `toast` object any Client Component can call (`toast.add({ title, type })`) without a provider, only the `<Toaster>` mounted once in the root `layout.tsx` needs to exist for it to render. Reuse this pattern for success/error feedback on new mutations rather than inventing another notification mechanism.

**GoTrue's `additional_redirect_urls` must exactly match the host AND scheme the app is actually opened at, or it silently falls back to `site_url` instead of erroring.** Hit live on 2026-09-05 with a real Google/PUCP SSO login: `supabase/config.toml`'s `[auth]` had `site_url = "http://127.0.0.1:3000"` and `additional_redirect_urls = ["https://127.0.0.1:3000"]` (wrong scheme, and neither entry included `/auth/callback` at all), while this app is actually opened via `http://localhost:3000` in dev. `auth-modal.tsx`'s `handleGoogle()` computes `redirectTo: `${window.location.origin}/auth/callback`\`, which became `http://localhost:3000/auth/callback`, not on the allow-list. GoTrue didn't reject the request, it silently substituted `site_url` as the final redirect target, so after a real, successful PUCP SSO login the OAuth `code` landed on plain `/` (Comunidad) instead of hitting `/auth/callback` to actually exchange it for a session, i.e. the whole flow looked like it worked but the person just ended up back at the public feed, still logged out. Fixed by setting `site_url = "http://localhost:3000"` and `additional_redirect_urls` to the exact URLs this app can be opened at (`http://localhost:3000/auth/callback`, `http://127.0.0.1:3000/auth/callback`, `http://127.0.0.1:3000`), then `supabase stop && supabase start` for local (confirmed via `docker exec supabase_auth_nouttbuk env | grep URI_ALLOW`), and `supabase config push --project-ref iyzannepoeygzzyqnztv` for cloud. Verified with a real end-to-end Google/PUCP login landing correctly on `/perfil`. **`config push` overwrote the cloud project's `site_url`/`additional_redirect_urls` with these same localhost values** since it syncs the whole `[auth]` section, not just the fields that were actually meant to change, this is harmless right now (nothing is deployed yet) but MUST be revisited the moment Vercel is deployed: update `config.toml`'s `site_url` to the real Vercel domain and add `<vercel-domain>/auth/callback` to `additional_redirect_urls` (keep the localhost entries too, for continued local dev), then `config push` again, or the exact same silent-fallback bug will reproduce in production.

**A `Link` inside `AuthModal` navigates but does not close the modal on its own.** `AppShell` owns the modal's `open` state and it isn't tied to the route, so a plain `<Link>` in `auth-modal.tsx` (e.g. the "Términos de uso"/"Política de privacidad" footer links) will correctly navigate to the destination page underneath, but the dialog itself stays open on top of it, visually blocking a page that isn't actually gated (this looked exactly like "I need to log in to see this" even though the page rendered fine). Fixed by adding `onClick={() => onOpenChange(false)}` to those links; any future link added inside the modal needs the same treatment.

## Language rule for all user-facing text

All copy (UI strings, error messages, docs, comments, and any reply written in this project) must be in **neutral/standard Spanish** ("tú" forms). Never Rioplatense/Argentine Spanish (no "vos", no voseo conjugations like "tenés"/"podés"/"hacé"). This has been corrected multiple times in this project; treat it as a hard constraint, not a style preference, and re-check any generated string against it before finalizing. Also avoid em dashes as a sentence/clause separator, use commas or split sentences instead; this is a separate, equally strong standing preference in this project.
